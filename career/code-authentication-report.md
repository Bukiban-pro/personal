## Code Evidence per Skill

### Spring Boot 3.4 / Java 21
- `spring-boot-starter-parent:3.4.4` in pom.xml
- `<java.version>21</java.version>`
- Java 21 records for all DTOs (zero boilerplate)

### REST API Design
- `@RestController @RequestMapping("/api/v1/payments")`
- POST returns `201 CREATED`, GET returns `200 OK`
- POST process/refund: state transitions return `200 OK`
- Consistent URL pattern: `/api/v1/payments/{id}/action`

### JPA / Hibernate
- `@Entity @Table(name = "payments")` with `@Id @GeneratedValue`
- `@Enumerated(EnumType.STRING)` for status
- `@PrePersist` lifecycle callback
- `JpaRepository` with 3 custom query methods
- `@Column(precision = 10, scale = 2)` for monetary amounts

### Validation
- `@Valid` on controller parameter
- `@NotBlank`, `@NotNull`, `@DecimalMin`, `@DecimalMax`, `@Size`
- Custom error messages for every constraint

### Error Handling
- `PaymentNotFoundException` custom exception extends `RuntimeException`
- `@ExceptionHandler` maps to 404 and 409
- Error messages include entity ID and current state

### Testing
- 8 unit tests (Mockito + JUnit 5)
- 9 integration tests (MockMvc + SpringBootTest)
- Covers: happy path, not-found, illegal-state, validation errors, idempotency
- `verify(repository, never()).save()` on guard conditions

### Design Patterns
- **State Machine**: guarded transitions, 5 states
- **DTO (Record)**: immutable in/out data contracts
- **Static Factory**: `PaymentResponse.from(entity)`
- **Repository**: Spring Data JPA abstraction
- **Constructor Injection**: no field injection
- **Idempotent Operation**: refund on already-refunded is safe

### Containerization
- `eclipse-temurin:21-jre-alpine` (93 MB base)
- `docker-compose.yml` with profile-aware config
- Two Spring profiles: dev (H2 in-memory), docker (H2 file-based)
- README documents PostgreSQL swap path
